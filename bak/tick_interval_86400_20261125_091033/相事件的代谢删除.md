# 相事件的代谢删除

## 1. 相事件的定义

相事件是活跃事件表 `ains_active_nodes` 中 `block_tag = '相'` 的事件。它用于表达为自洽、配平已有因果连线，或推导可能后续而假定、写入的虚拟事件。

## 2. 当前配置

配置文件：`/root/causal_ai/.env`

```env
TICK_INTERVAL = 60
XIANG_FORGET_THRESHOLD = 0.001
```

- 代谢引擎每 60 秒执行一次检查和清理。
- `XIANG_FORGET_THRESHOLD` 是现有用户副本平均生存权重的删除阈值。
- 配置在应用启动时加载；修改后需要重启服务才能生效。

## 3. 自动删除条件

事件必须满足 `block_tag = '相'`，并满足以下任一条件：

1. **没有任何用户副本**：直接进入删除候选，在下一次代谢时执行删除，不检查权重。
2. **存在用户副本**：该事件所有现有用户副本的 `survival_weight` 平均值小于或等于 `XIANG_FORGET_THRESHOLD`。

当前条件的 SQL 表达为：

```sql
SELECT b.serial_id, b.node_id
FROM ains_active_nodes b
LEFT JOIN ains_user_weights a ON a.serial_id = b.serial_id
WHERE b.block_tag = '相'
GROUP BY b.serial_id, b.node_id
HAVING COUNT(a.actor_id) = 0
    OR AVG(a.survival_weight) <= %s
```

这里使用 `LEFT JOIN`，因此没有用户副本的相事件也会进入候选，不会再被连接查询漏掉。

### 判定口径

- “平均权重”只统计已经存在于 `ains_user_weights` 中的副本，不统计尚未创建副本的注册用户。
- 判断依据是用户副本权重平均值，不是 `ains_active_nodes.survival_weight` 全局权重。
- 判断使用 `<=`，平均值恰好等于阈值时也满足删除条件。
- 观测点击会将当前用户对目标事件的权重提升至 `0.60`，通常会提高平均值并使其暂时脱离候选；后续观测其他事件时，该权重仍可能重新下降。

## 4. 代码位置

- 候选查询：`core/database.py` 的 `get_zero_weight_xiang_nodes()`。
- 阈值读取：`core/metabolism.py` 的 `MetabolismEngine.__init__()`。
- 定时清理：`core/metabolism.py` 的 `_metabolic_tick()`。
- 服务启动代谢任务：`main.py` 的 `startup_event()`。

## 5. 删除执行流程

每次代谢滴答先处理相事件候选，再执行普通事件代谢：

1. 查询无用户副本或平均权重达到阈值的相事件。
2. 按 `node_id` 再次确认事件仍然存在。
3. 删除地宫表 `ains_archive_necropolis` 中对应的原始内容。
4. 删除活跃表 `ains_active_nodes` 中的事件记录。
5. 用户权重表 `ains_user_weights` 中的副本记录通过外键 `ON DELETE CASCADE` 级联删除。
6. 如果事件具有 `/uploads/raw/` 下的原始图片，尝试删除对应图片文件。
7. 重组子事件连线：
   - 被删事件存在前事件时，子事件继承这些前事件。
   - 被删事件没有前事件时，子事件移除该引用；没有其他前事件时成为根事件。
8. 广播 `node_deleted`，通知前端移除事件节点。
