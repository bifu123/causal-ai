# 鉴权升级方案（最终版）

> 状态：已确认，按本方案实施。
> 范围：URL token/edit 权限、actor 管理、用户副本、admin 管理。
> 不在本次范围：非注册 actor / 无主场清理；后期由数据库触发器实现，不改造代谢引擎。

## 一、核心原则

1. 所有用户都属于观测者。观测者可以观测任何 owner 场。
2. URL 中只要同时存在 owner_id 和 actor_id，该 actor 就拥有该场的用户副本。
3. 用户副本保存在 ains_user_weights：
   - survival_weight：该 actor 自己的权重；
   - parent_id：该 actor 自己的因果连线。
4. 读取权重和 parent_id 时，以用户副本为宗；副本没有记录时才回退到场主主副本。
5. 未注册观测者不需要 token，也可以写自己的副本（点击提权、编辑 parent_id）。
6. token 用于区分观测者 / 场主 / admin：
   - token 属于该 owner 场主 actor：场主全部权限；
   - 其他有效 token：观测者权限；
   - 无 token：匿名观测者，只读共享内容。
7. edit 只决定“点击节点是否打开抽屉”，不直接决定写权限。
8. 场主修改主副本 parent_id 时，同步更新场主自己的用户副本，避免自己的视图被旧副本遮蔽。

## 二、角色与权限矩阵

| 访问者 | 判定条件 | 读 | 写 |
|---|---|---|---|
| 匿名观测者 | 无 token，且 URL 无 actor_id | 本场 is_share=true 节点；接触面 is_share=true 内容；未分享异场节点打码 | 无；即使 edit=true，抽屉也只读 |
| 观测者 | URL 有 actor_id，或任意有效非场主 token | 本场 is_share=true 节点；接触面 is_share=true 内容 | 写自己的副本：权重、parent_id；滑杆可用；抽屉中仅 parent_id + 保存可用 |
| 场主 | token 属于 ains_owner_masters.owner_id 对应 actor | 本场全部节点 + 接触面 is_share=true 内容 | 主副本完整权限：内容、标签、node_id、parent_id、is_share、删除、又贞/对贞、上传、贞图标 |
| admin | ains_users.is_admin=true 或 ADMIN_ACTOR_IDS 指定 | 任意场全部节点 + 接触面 | 任意场主副本完整权限 + actor 管理 |

## 三、用户副本规则

### 3.1 访问时自动建立副本

在 /api/v1/causal/history 加载节点时：

1. 对本场每个有 serial_id 的节点，若 ains_user_weights 没有该 actor 记录：
   - survival_weight = 场主节点权重；
   - parent_id = 场主节点 parent_id；
   - 若场主 parent_id 为 NULL，用户副本写入空字符串 ''，表示“副本中明确无父节点”，避免以后场主新增父节点时被回退覆盖。
2. 若已有记录但 parent_id IS NULL（旧版本遗留）：
   - 视为尚未初始化，用场主 parent_id 回填；场主为空则写入 ''。
3. 已有用户记录的权重和 parent_id 不覆盖，保证“副本为宗”。

### 3.2 读取时应用副本

1. /api/v1/causal/history：
   - 权重：用户副本 survival_weight 优先，缺失时用全局权重；
   - 连线：用户副本 parent_id 非 NULL 时优先，'' 表示无父节点；NULL 才回退全局。
2. core/search.py 的 get_event_by_sid：
   - 权重已支持用户副本；
   - 增加用户副本 parent_id 覆盖；
   - 父列表和子列表都使用有效 parent 表达式：
     CASE WHEN w.parent_id IS NULL THEN n.parent_id ELSE w.parent_id END。
3. db.get_node_links(node_id, actor_id=None, owner_id=None)：
   - 增加 actor_id 参数；
   - 父/子查询都应用用户副本 parent_id。
4. get_event_skeleton 的递归 SQL：
   - 递归父边和子边都应用用户副本 parent_id。
5. get_cross_field_contact_surface：
   - 已使用 COALESCE(w.parent_id, n.parent_id)，与本规则兼容，保留。

### 3.3 写副本

1. 新增 db.set_user_parent_link(actor_id, serial_id, parent_id_str)：
   - 明确写入 parent_id，支持普通字符串、''、None；
   - '' 表示无父节点；
   - 不覆盖权重。
2. /api/v1/causal/update：
   - 观测者：只接受 previous_ids，写入自己的副本；其他字段全部忽略/拒绝；
   - 场主/admin：更新主副本 ains_active_nodes.parent_id，同时把该场主自己的副本 parent_id 同步为相同值；
   - 其他观测者的副本不受影响。
3. /api/v1/causal/click、/promote_chain：
   - 有 actor_id：权重写入该 actor 的副本（现有逻辑保留）；
   - 无 actor_id：仅场主/admin 可写主副本；
   - 观测者重排只使用可见节点，避免把私有节点纳入其权重分配。

## 四、URL 参数

### 4.1 edit

- edit=true：点击节点打开抽屉；
- edit=false 或缺省：点击只聚焦/提权，不打开抽屉；
- edit 不再要求 localStorage 必须有 token；
- 抽屉打开后，具体可编辑项由角色决定。

### 4.2 token

- token 来源优先级：URL token > localStorage 缓存；
- URL token 有效时写入 localStorage，供后续页面复用；
- URL token 无效时不回退旧 token，提示“钥匙无效”，按匿名观测者处理；
- token 有效时，token 反查出的 actor 优先于 URL 中的 actor_id，防止冒名。

### 4.3 token 缓存

- /auth 增加“用钥匙快速进入”入口：
  - 输入 token（可选 actor_id）；
  - 调 /api/v1/auth/token/verify 验证；
  - 成功后写入 causal_token、causal_actor_id；
  - URL 带 token 时自动验证并缓存，再清理地址栏。
- 登录、注册、签发钥匙后继续写 localStorage；
- 退出登录同时清空。

## 五、读权限与展示

1. 本场节点：
   - 场主/admin：全部节点；
   - 观测者/匿名：仅 is_share=true 节点。
2. 异场接触面：
   - 仅 is_share=true 返回内容；
   - is_share=false 保留打码桩点，返回“【私密桩点】内容不可见”，不返回 full_image_url。
3. 语义连线：
   - 只保留两端都可见的节点；
   - 不向观测者返回涉及私有节点的连线。
4. 可见节点的 previous_ids/next_ids：
   - 裁剪到可见节点集合，避免通过连线泄漏私有节点 ID。
5. 搜索、相似节点、骨架：
   - 全部按上述可见性过滤；
   - 观测者不得拿到私有节点的 event_tuple/full_image_url。

## 六、后端改造

- resolve_access(request, data=None, owner_id=None, actor_id=None)：
  - token 来源：auth_token → Authorization: Bearer → token query/body；
  - 用 db.get_actor_by_token(token) 反查 actor；
  - 用 db.get_owner_master(owner_id) 判断场主；

- 读过滤函数：

  - sanitize_nodes(nodes, access)；
  - 返回给前端的 access 对象。

### 6.3 Socket.IO 隔离

1. 前端建连带 owner_id/actor_id/token。
2. 连接时按访问上下文加入房间：
   - field:{owner_id}:public
   - 场主/admin 再加入 field:{owner_id}:private
   - 有效 token 再加入 actor:{actor_id}
3. 初始推送只发过滤后的节点。
4. 全局私有更新只发 private room；公开更新发 public+private；观测者副本更新只发 actor:{actor_id}。
5. 避免私有节点内容广播给所有客户端、仅靠前端过滤。

## 九、Admin 管理（定位：场主管理局）

1. admin 判定（三者之一，**都必须携带有效 token**）：
   - **内置写死**：`actor_id == 'admin'`（`core/access.py::BUILTIN_ADMIN_ACTORS`；不可降权、不可注销）；
   - `ains_users.is_admin` 或 `.env` 的 `ADMIN_ACTOR_IDS`；
   - URL `actor_id` 不授予 admin / 场主。
2. 本职四件事：
   - 看现在有哪些场主（`GET /api/v1/admin/owners`）；
   - 进入场主的 /auth 账号中心，以他身份执行一切操作（`GET /api/v1/admin/actors/{actor_id}` 取 `first_token`，前端内存态使用）；
   - 注销场主及其名下所有房产（`POST /admin/actors/{id}/delete`）；
   - 为场主重置 token（`POST /admin/actors/{id}/token/reset`）。
3. 删除场主：逐场 `delete_owner_all()`（活跃节点 + 地宫 + 用户权重 + 场注册 + 跨场父子引用），再删副本与 `ains_users` 行；禁止删除自己、禁止删除最后一个 admin。
4. admin 不再承担“代客改内容”的职责：要改某个场的内容，走“进入该场主账号中心”，以场主身份操作。

## 十二、admin 场主管理（第二轮改造，已完成）

> admin 的定位从“场内容编辑工”收敛为**场主管理局**：看有哪些场主 → 进入其账号中心（以他身份操作）→ 重置 token → 注销并删除全部场。

### 13.1 安全前提（Step 0）

`core/access.py` 收紧身份来源：**只有有效 token 才能成为场主 / admin**。
URL 中的 `actor_id` 仅用于建立该观测者的用户副本（仍可写副本），不再授予 owner/admin。

```python
token_is_admin = bool(token_valid and token_actor and (
    db.is_admin_actor(token_actor) or token_actor in _admin_actor_ids()))
is_owner = bool(token_valid and token_actor and master_actor and token_actor == master_actor)
```

实测：`?owner_id=X&actor_id=<场主>` → `observer`；`?actor_id=<admin>` → `observer` 且 `/admin/*` 全拒。

### 13.2 新增接口

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/v1/admin/owners` | GET | 场主聚合：场主 actor、名下场（含节点数）、场数、节点总数、钥匙数、is_admin |
| `/api/v1/admin/actors/{id}/token/reset` | POST | 吊销该 actor 全部旧钥匙并签发一把新钥匙（返回明文 + 吊销把数） |
| `/api/v1/admin/actors/{id}` | GET | 已有，返回 `first_token` 供「以该场主身份进入」 |
| `/api/v1/admin/actors/{id}/delete` | POST | 已有，逐场 `delete_owner_all` + 删账号 + 删副本 |

### 13.3 数据库

- `list_owner_actors(limit)`：单次聚合查询（场 + 各场节点数 + 钥匙数 + admin 标记），按场数/节点数降序
- `reset_actor_tokens(actor_id)`：`set_user_tokens(actor_id, [new_token])`，返回 `{token, revoked_count}`

### 13.4 前端（/auth）

1. 新增 `ACT_AS = { actor, token }` **内存态**代管身份，不写 `localStorage`；刷新即回 admin。
2. `currentActor()` / `authToken()` 两个取值器替换全部 `LS.actor` / `LS.token` 读取；
   登录、注册、退出、手动换钥匙仍写 `localStorage`。
3. 顶部金色横幅：`管理员视角：正在以 <actor> 的身份操作｜退出管理员视角`。
4. admin tab 改为**场主卡片**：场主 + admin 标记 + 场数/节点数/钥匙数 + 各场明细 + 四个按钮
   （进入其账号中心 / 重置token / 设为取消admin / 注销并删除全部）。
5. 重置 token 弹窗：显示被吊销把数与新钥匙（仅一次）+ 复制按钮。
6. 注销：两次确认，第一次列出将删除的场清单与节点数。
7. 保护：自己的卡片“注销”按钮 disabled；后端仍拦“不能删除自己 / 最后一个 admin”。

### 12.2 关键实现约定

1. **副本为宗的三种状态**：`NULL` = 未初始化（回退主副本）；`''` = 明确无父节点；其它 = 副本连线。
2. **子链匹配**使用 `POSITION(chr(124) || id || chr(124) IN chr(124) || parent || chr(124))`，
   避免 `LIKE '%|'` 中的 `%` 被 psycopg2 当作占位符。
3. **`get_event_horizon` 占位符顺序**必须与 SQL 文本一致：距离子查询 → 子链 JOIN → 主表 JOIN → WHERE 三处 → 场过滤。
4. **旧数据兼容**：`is_share` 为 `NULL` 视为共享（`is_shared`），避免升级后历史内容突然全部不可见。
5. **编辑 UI**：`owner-edit-only` 需同时满足 `edit=true` 与 `can_write_master`；
   `copy-edit-only` 需同时满足 `edit=true` 与 `can_write_copy`。

## 十四、admin 职责

早期描述把 admin 写成了“场内容编辑工”，已纠正。admin 的本职只有四件事：

1. **看现在有哪些场主**（谁有房、几套、各套多少节点）
2. **进入场主的 /auth 账号中心**，像他本人一样执行一切操作
3. **注销场主及其名下所有房产**
4. **为场主重置 token**

对应实现见 §12：
- `GET /api/v1/admin/owners` — 场主聚合列表
- `GET /api/v1/admin/actors/{id}` — 取 `first_token` 以场主身份操作（前端内存态，不写 localStorage）
- `POST /api/v1/admin/actors/{id}/token/reset` — 重置钥匙
- `POST /api/v1/admin/actors/{id}/delete` — 注销场主并删除全部场

> admin 不再承担“代客改内容”的职责：要改某个场的内容，走“进入该场主账号中心”，以场主身份操作。



在URL中edit=true前提下，token还决定了抽屉内表单的元素可操作/可见
无token/错误的token视为普通观测者，表单中只有父节点 ID (Parent IDs) d-parent-ids和btn-save-node可操作，并且btn-create-node不可用
