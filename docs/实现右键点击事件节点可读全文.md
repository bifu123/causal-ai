### 当前 URL 聚焦的缺陷
目前 `static/js/3d_main.js` 中的逻辑是：前端解析到 URL 中的 `serial_id` 后，会等待图谱渲染完成，然后**在当前已加载的节点中查找**该节点。如果找到了，才调用聚焦接口。
**问题在于**：如果该节点因为权重过低已经沉入“地宫”，它就不会出现在当前加载的节点列表中，导致前端提示“未在当前图谱中找到节点”并放弃聚焦。这与 `search_causal_by_serial` 能够“自动从地宫恢复”的强大逻辑不符。

### 优化计划
为了真正实现与 `search_causal_by_serial` 相同的逻辑，我们需要做以下小幅调整：

1. **修改 `static/js/3d_main.js` 中的 URL 聚焦逻辑**：
   不再依赖前端图谱中是否存在该节点，而是直接调用后端的 `/api/v1/causal/click` 接口（该接口内部已经实现了从地宫恢复节点、提升权重并广播视界更新的逻辑）。
   
2. **兼容 `nodeId` 为空的情况**：
   修改 `handleSearchResultClick` 函数，当通过 URL 触发时（此时前端还不知道 `nodeId`），从后端返回的数据中提取 `node_id` 用于 UI 提示。
